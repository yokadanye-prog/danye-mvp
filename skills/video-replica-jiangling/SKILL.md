# video-replica-jiangling（视频复刻画布）

把用户提供的一段本地原视频（≤30 秒），走一条四步固定画布，复刻成风格统一的分段视频。本 skill 是**编排器**：它串联三个既有能力，不在内部自行发明生成逻辑。

- 深度视频 → 用 `video-depth-anything` skill。
- 创意改编与提示词 → 用 `qisi-video-remix` skill。
- 图片生成 → quan 平台 MCP `quantv-generation`。
- 视频生成 → 当前 WorkBuddy 已安装的 quan MCP `quantv_generate_video`。

此 Skill 只编排工具调用，不携带任何 quan 凭证。使用者需要在自己的 WorkBuddy 中配置自己的 quan MCP。找不到 `quantv_list_models`、`quantv_generate_image`、`quantv_upload_media` 或 `quantv_generate_video` 时，停止对应生成步骤并说明缺少连接器，不读取本机配置文件，也不自行构造 HTTP 请求。

### 两个配套 Skill 的调用范围

`video-depth-anything` 在本编排中只执行深度提取与结果检查。其参考资料里的多个生成候选、重新生成建议不进入本任务；图片与视频的付费提交仍遵循主流程的逐段确认规则。

调用 `qisi-video-remix` 时，明确传入已经确认的题材、人物、场景与片段时间轴。本编排只使用其参考分析、身份图／造型图／场景图提示词和对应片段的动作描述，不启动它的独立故事重写与生成分段流程。主流程负责实际段长，不把片段扩展成十五或三十秒，也不虚构用户已选择过独立分段上限。用户另行要求完整故事改编时，再按 qisi 的原始规则确认单段上限与新的故事方向。

## 核心约束（铁律，不可违背）

1. **原视频不限总长**。按实际时长分段并逐段接力生成，支持把任意长度的原视频复刻成对应时长的成片；段长仍落在 4–7s 区间（优先按硬切点、7s 均分作备用），末段按剩余时长处理。
2. **只使用当前 WorkBuddy 用户自行配置的 quan 连接器**。允许用 `quantv_get_task` 查询结果，但**每张图、每段视频只允许发起一次生成请求**；失败即停，等用户决定，不自动重试、不自动二次扣费。
3. **wan3 的参考视频总和 ≤ 15 秒**。每段 = 原视频对应段 + 深度视频对应段，两段合计需 ≤15s。
4. **段与段之间不从头读取**。原视频与深度视频按同一时间轴逐段下移（0→末），不是每段都从 0 读。
5. **每一段生成后，必须交用户确认，才能进下一段**。图片资产也由用户逐张确认，够了才继续。
6. **末帧接力（人物一致性铁律，强制默认）**。每一段成片生成并确认后，必须用 `ffmpeg` 从该段成片中抽取**最后一帧图像**，上传后作为**下一段** `imageUrls[]` 的「上段末帧人物参考图」。通过「上一段末帧 → 下一段人物参考」的逐段接力，锁定同一人物形象，保证跨段人物一致性。只有用户明确说「本段不用末帧」才跳过。

## 凭证与分享边界

1. 分享完整套件时保留 `skills/` 下三个 Skill 的文件、依赖说明和许可证。不要附带 WorkBuddy 的 `mcp.json`、个人 Quan MCP 程序配置、Python 虚拟环境、模型权重、日志或任何令牌。
2. Skill 不读取、显示、复制 `QUANTV_ACCESS_TOKEN` 或 `QUANTV_REFRESH_TOKEN`。所有 Quan 操作只能通过当前用户已安装的 MCP 工具完成。
3. 他人在自己的电脑安装此 Skill 后，如果没有用自己的 Quan 账户配置 MCP，Quan 生成步骤必须停止。不得借用作者的账号、共享令牌或改用直接 HTTP 调用。

## 分段策略（已定）

- **优先按硬切点拆段**：用 `ffprobe` 检测换装/转场等硬切，在硬切点切段。这样每段是一个完整镜头语义，最省生成时间、复刻最准。
- **7 秒均分是备用**：当某段没有硬切、或硬切间隔过长时，按 ≤7s 切，避免单段超 wan3 的合理控制长度。
- 段数不限（放开原 ≤4 上限）。每段时长落在 4–7s 区间（末段按剩余时长，可能 <4s，届时如实说明并让用户确认是否并入上一段或单独成段）。长视频按实际时长拆成多段后，依靠「末帧接力」逐段推进。

## 四步流程

### Step 0：收原视频

- 先完成上面的首次启动检查；缺项时停在准备阶段。
- 用户提供本地视频路径（时长不限，按实际时长拆段接力）。
- 用 `ffprobe` 核对：时长、分辨率、帧率，并检测硬切点（换装/转场）。
- 输出分段方案给用户确认：优先按硬切点切，7s 均分作备用，段数不限（按实际时长）。

### Step 1：生成深度灰色视频（并逐段切好）

- 调用 `video-depth-anything` skill，产出与源视频同时间轴、同动作的灰度深度参考视频（无音频）。
- 深度视频**必须交给用户查看、确认效果**，确认后才进入 Step 2。
- 确认后，**按 Step 0 已定的分段方案，把深度视频逐段切好**，与原视频各段一一对应（同一起止时间）。
- 深度视频仅作控制参考，不是成片。

### Step 2：图片资产生成（quan）

- 由 `qisi-video-remix` 产出「身份图提示词 / 造型图提示词 / 场景图提示词」。
- **先生成前，先跑一次 `quantv_list_models`，把可用图片模型的候选清单列给用户挑选**（含模型名与档位），不要口头凭空点名。
- 用户拿着这些提示词，通过 quan 平台生成图片。**生成几张由用户决定**，你按用户给的提示词逐张调用生成。
- 图片生成走 `quantv_generate_image`，参数模板：
  - 模型 `modelId`：以 `quantv_list_models` 实时返回为准（用户从候选清单挑选）。
  - 分辨率 `resolution`：`1K | 2K | 4K`。
  - 尺寸 `ratio`：`1:1 | 3:2 | 2:3 | 16:9 | 9:16 | 5:4 | 4:5 | 4:3 | 3:4 | 21:9 | 9:21 | 2:1 | 1:2`（以实时返回为准）。
  - 提示词 `prompt`：用户提供（或 qisi 产出）。
- **每张图只允许一次生成请求**。`forceNew` 仅在用户明确要求「再次扣费生成全新结果」时填 `CONFIRM_NEW_CHARGE`，网络错误重试绝不填。
- 用户逐张确认图片资产，明确表示「图片够了」才进入 Step 3。

### Step 3：第一段视频生成（wan3）

- 再次调用 `qisi-video-remix`：参考「原视频素材 + 深度灰色视频素材」，读取**第一段对应时间轴**内容，产出第一段的视频生成提示词。
- 本地参考素材先逐个调用 `quantv_upload_media`，将返回的 `url` 放入视频工具对应的素材数组。
- 视频生成调用 `quantv_generate_video`，参数：
  - 时长 `duration`：按已经确认的分段方案，通常每段 4 至 7 秒，并在实时工具 Schema 允许范围内；末段不足最小时长时先由用户确认调整。
  - 画面比例 `ratio`：16:9 | 9:16 | 1:1 | 4:3 | 3:4（用户选）。
  - 分辨率 `resolution`：**480p | 720p | 1080p**（wan3 实际档位）。
  - `videoUrls[]`（参考视频，≤2 段）：原视频对应段 + 深度视频对应段（两段合计 ≤15s）。
  - `imageUrls[]`（参考图，≤10 张）：角色资产图 + 造型图 + 场景图 + **上段末帧人物参考图（第二段起必带，见「末帧接力」）**。第一段没有上段末帧，仅用角色资产图 + 造型图 + 场景图。
  - `promptExtend`：false（不拓展提示词）；`audio`：false（不生成音频）。
- **每段只允许一次生成请求**；失败即停，交用户决定。
- 提交后保存返回的任务 ID，约每 15 秒调用 `quantv_get_task` 查询。查询失败时保留任务 ID，避免重复提交。
- 生成后交用户确认，确认后才进 Step 4。

#### 视频生成提示词规范开头（每次生成 wan3 视频必须先用这段）

写每段 wan3 视频提示词时，**先用下面这段固定「素材参考」开头**（把 @ 占位换成实际素材绑定），再在末尾接 `qisi-video-remix` 分析出的动作时间线。不要凭想象改动作。

```
人物形象参考图与造型图，场景参考图。动作与镜头参考 原视频 与 深度灰色视频，按时间线连贯推进：严格将 原视频 中的模特替换成 模特造型图，复刻准确的身体动作、手部轨迹、表情时序、手中的手枪、人物站位、固定机位和运镜节奏，不继承他的脸、五官、身份和外貌。严格遵循 深度灰色视频 中人物的运动轨迹、步伐节奏、重心变化与镜头推近幅度；深度灰色视频 只提供动作与构图，不继承其灰度画面，成片必须还原为彩色实拍色调。
严格使用 模特造型图 生成片中唯一人物，模特角色四视图 用于确认该角色服装的正面、侧面、背面与 45 度细节，不得改变配色与款式；场景图 是背景图，不得随便变换场景。
```

- 素材绑定关系（@ 名称 ↔ MCP 参数）：`原视频` / `深度灰色视频` → `videoUrls[]`；`模特造型图` / `模特角色四视图` / `场景图` / `上段末帧人物参考图` → `imageUrls[]`。
- 第二段起，`上段末帧人物参考图` 作为锁定同一人物形象的首要参考，与 `模特造型图` 共同约束人物外观；两者描述的人物必须是同一人。
- 之后才是画面规格（风格、比例、时长、分辨率）与动作时间线（由 `qisi-video-remix` 按帧识别产出，逐秒列出）。

#### 素材上传与任务查询

`quantv_upload_media` 接收本地文件绝对路径，使用当前 WorkBuddy 连接器上传到 Quan 自有存储，并返回素材网址。图片网址传给 `quantv_generate_video.imageUrls`，视频网址传给 `videoUrls`，音频网址传给 `audioUrls`。图片最多 10 张，视频最多 2 段，音频最多 2 段。生成工具返回任务 ID 后，用 `quantv_get_task` 查询结果。整个流程无需访问第三方图床，也无需读取任何令牌文件。

### Step 4：后续分段视频生成（循环 + 末帧接力）

- 对每一段重复 Step 3，但读取的是**原视频与深度视频的下一段**（不从头）。
- **每段生成并确认后，先抽取该段成片的最后一帧**（见下「末帧接力」），作为下一段 `imageUrls[]` 的「上段末帧人物参考图」，再进入下一段。
- 每段生成后都交用户确认，再进下一段。全部段落完成后流程结束。

#### 末帧接力（人物一致性，第二段起每段必做）

1. **抽帧时机**：某一段 wan3 成片生成完成、且经用户确认满意后，**立即**用 `ffmpeg` 抽取该段成片的最后一帧，保存为 JPG（例如 `-sseof -0.1 -i 成片.mp4 -frames:v 1 -q:v 2 末帧.jpg`，抽的是成片最后一帧画面）。
2. **上传**：用 `quantv_upload_media` 上传该末帧 JPG，拿到 Quan 直链。
3. **接力**：把该末帧直链作为下一段 `quantv_generate_video.imageUrls[]` 里的「上段末帧人物参考图」，并在提示词里声明它用于锁定同一人物外观（与造型图共同约束，人物为同一人）。
4. **默认强制**：末帧接力默认开启，无需用户每次确认；仅当用户明确说「本段不用末帧」才跳过。
5. **异常处理**：若抽帧或上传失败，停下来向用户说明，由用户决定是否改用角色造型图作下一段参考、或先修复抽帧环节，不静默跳过。
