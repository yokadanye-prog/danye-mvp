# 环境与踩坑

## 环境

跑起来需要三样东西：Python 3.10+（带 `pyJianYingDraft==0.3.1`、`Pillow`）、`ffprobe`、`coli`。

### 先看有没有现成的

```bash
python scripts/quan_story.py doctor
```

工坊会按顺序找运行时配置：

1. 环境变量 `QUAN_STORY_CONFIG` 指向的文件
2. `%LOCALAPPDATA%\quan-story-studio\runtime.json`
3. `%LOCALAPPDATA%\story-studio\runtime.json` ← **装了 story-studio 就直接命中，无需重装**

命中第 3 项时，`python`（装了 pyJianYingDraft 的那个解释器）、`coli_bin`、`drafts_root` 全部继承。导出脚本会自动用那个解释器重跑，所以用系统 Python 调也没关系。

### 没有现成的就建一个

```bash
python -m venv "%LOCALAPPDATA%\quan-story-studio\venv"
"%LOCALAPPDATA%\quan-story-studio\venv\Scripts\python.exe" -m pip install pyJianYingDraft==0.3.1 pillow
```

然后写 `%LOCALAPPDATA%\quan-story-studio\runtime.json`：

```json
{
  "python": "C:/Users/<你>/AppData/Local/quan-story-studio/venv/Scripts/python.exe",
  "drafts_root": "C:/Users/<你>/AppData/Local/JianyingPro/User Data/Projects/com.lveditor.draft"
}
```

`ffprobe` 来自 ffmpeg；`coli` 是本地转录 CLI，装不上时可以让用户直接给 SRT（`--timing xxx.srt`），精度会从字级退到句级。

### 草稿目录定位

顺序：`--drafts-root` → `JY_PROJECTS_ROOT` → runtime.json 的 `drafts_root` → 剪映 `globalSetting` 里的 `currentCustomDraftPath` → 标准路径。都找不到时让用户打开剪映"设置 → 草稿位置"看一眼，不要让他复制一堆路径。

## 踩坑清单

### 1. 配音"重新生成"了，其实没变

**症状**：重调一次语音生成，返回的时长一秒不差，MD5 也一样。

**原因**：平台对"同文本 + 同音色"做了去重缓存。

**处置**：确认用户真的要重做，再加 `forceNew: "CONFIRM_NEW_CHARGE"`。这是重新计费的动作。网络错误的重试绝对不要加。

### 2. 音色不对，但文件名看不出

**症状**：用户说"声音和参考视频不是同一个人"。

**原因**：项目里躺着两个都叫"完整版"的文件，一个 333 秒（旧音色，错）、一个 293 秒（目标音色，对）。差 40 秒才让人发现问题。

**处置**：文件名带时长或音色标记，例如 `梅兰芳_完整版_293s.mp3`。核对音色的唯一可靠方式是**让用户听**，不是看时长、不是看参数。

### 3. 配音时长和预期差一大截

**症状**：文稿 1935 字，本该 5 分 34 秒，出来只有 4 分 53 秒。

**处置**：先 `probe` 看语速。落在 4.5–5.8 字/秒就是正常音色换了语速；否则是文本被截断或音色仍是旧的。真要拉长，用 `atempo`（见 `voice.md` 末尾），不要重录。

### 4. 某张图死活生成不出来

**症状**：连续超时或审核失败。

**原因**：提示词写太满，"卖画度日、神情落寞、窗外灰暗天空、宣纸笔墨"这种堆砌反而容易卡。

**处置**：简化成"谁、在哪、做什么"，去掉抽象词。两次不成就换景别（特写改中景、正面改背影）。

### 5. 画面里出现看不懂的字

**症状**：霓虹灯牌、海报、报纸上是形似汉字的乱码。

**原因**：模型不会写汉字，但会"假装写"。

**处置**：提示词里"无文字"不够，要写**画面不出现任何文字**，并具体点名高危物件（招牌、海报、书页、锦旗）。涉及海外场景（百老汇、唐人街）时尤其容易翻。

### 6. 该黑白的出了彩色

**症状**：提示词写了"黑白叙事"，出来是低饱和彩色。

**处置**：把"纯黑白灰阶，不带暖褐、泛黄或蓝色偏色"写进风格句第一句，并删掉原风格句里的"色彩低饱和"——两套句尾会互相拉扯。

### 7. 草稿改不动了

**症状**：`draft_content.json` 变成一长串 base64。

**原因**：剪映打开过这个草稿，内容被加密。

**处置**：不要解密、不要原地改。新开一个草稿名重导，旧草稿给用户自己删。

### 8. 语速想调 0.88，接口不认

**原因**：`quantv_generate_speech` 的 `speed` 只有 `0.5 / 1 / 2`。

**处置**：用 ffmpeg `atempo`，保持音高。而且变速是线性的，分镜时间按同比例缩放即可，**不需要重新转录对齐**。

### 9. 音频时长两个工具报得不一样

**症状**：ffprobe 报 333.58，草稿校验说超了一帧。

**原因**：MP3 带 Xing 头，流时长和容器时长各算一遍。

**处置**：`ffmpeg -c:a libmp3lame -b:a 192k -write_xing 0` 重编码成 CBR，两个探测就一致了。

### 10. 分镜时间靠均分，画面和旁白错位

**症状**：每镜时长整齐划一（8.1 秒），但某几镜明显"话说完了图还没切"。

**原因**：均分假设每句字数一样，实际有长句短句。

**处置**：用 `build` 的锚点定位，走字级时间戳。实测 41 镜里 31 镜能精确命中、10 镜靠相似度定位，插值 0 镜；比均分准得多，也比手工调快得多。

### 11. 换了配音，图全要重排吗

**不用。** 跑 `realign`，按字符位置把镜界搬到新时间轴，图、顺序、提示词一个都不动。

### 12. 图片比例不对

**症状**：草稿里图片两边留黑边。

**原因**：图是 1:1 或 3:4，plan 是 9:16。导出脚本用 cover 铺满并留 4% 余量给推拉，比例差太多会裁掉主体。

**处置**：生图时 `ratio` 必须是 `9:16`；`verify` 会检查每张图的比例，差超过 2% 直接报错。

### 13. 末镜黑屏

**症状**：最后一句还在念，画面已经结束。

**原因**：时间轴总长比配音短。

**处置**：`verify` 会报"时间轴 X 秒与配音 Y 秒相差 Z 秒"。回 `build` 重算，或把末镜 `end` 改成音频时长。导出脚本有一帧的自动补偿，但超过一帧就拒绝导出——这是保护，不是故障。
