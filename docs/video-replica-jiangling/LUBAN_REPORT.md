# Video Replica Jiangling 鲁班打磨报告

本轮目标是让分享后的用户拿齐配套文件，并准确知道深度环境与 Quan MCP 还需要安装什么。用户已经明确选择加入两个配套 Skill，因此按这个具体方向完成本地候选，无需再等待选择方案。验收范围为安装依赖，尚未重新运行深度推理或付费视频生成。

## 一 验料结果

真实问题成立：旧分享包只有主 Skill，接收者缺少两个配套目录。独特角度来自原片与深度参考同时间轴的工作流，以及逐段确认。安装理由是把素材准备、提示词和调用规则组织在一起。公共传播产物已有 Skill 文件，但完整视频演示仍缺。

结论：定位可用，本轮集中补安装依赖与首次检查。

## 三 生态位判断

当前作品是工作流编排 Skill。由私用走向可分享，先要让外部用户拿齐文件并看清自备运行环境。此次定位为“带完整配套 Skill 文件、在用户自己的 WorkBuddy 与 Quan 账户运行的参考视频复刻工作流”。

## 五 差距清单

当前仍有一个必要的外部依赖：用户需取得含素材上传与视频生成工具的个人 Quan MCP。截图教程里的基础生图语音插件不能单独满足视频流程，说明中已经显式阻断这种情况。

P1 项包括真实短视频从深度到付费成片的完整演示、二十九至三十秒输入的分段边界，以及固定提示词中具体道具的通用化。P2 项包括更多操作系统推理、公开安装命令与展示素材。

与同行相比，当前缺少完整演示、独立用户安装回放与跨平台推理记录；可继续积累的优势是双参考同时间轴、逐段确认和个人凭证分离。

## 六 三个方向与本轮选择

A 为只写依赖名称，改动少但文件仍不齐。B 为三个完整 Skill 加安装说明与只读检查，本轮按用户已明确提出的需求执行。C 为自动安装模型与 MCP，涉及大文件下载、用户环境变更与授权流程，留待独立任务。

## 七 本轮改写与验证门

主 Skill 首屏现在明确导入三个完整目录、深度环境与个人 MCP 条件，并指向安装指南。示例入口只做不扣费检查。工具检查区分 PASS、MISSING、UNVERIFIED。

深度分享版移除原作者工具路径与显卡默认假设，增加 ToolRoot／PythonPath。qisi 原文件保持来源与 MIT 署名，主编排通过职责范围防止独立故事与时长规则覆盖动作复刻。深度交接资料的多个付费候选建议被改为由主流程决定。

文本场景干跑包括“只安装主 Skill”和“基础 MCP 已连通但无视频工具”。候选能给出完整文件位置与具体缺项；基线没有这些安装入口。此对比是文档 dry_run，不冒充真实用户或模型回放。

## 八 README 与展示

新增套件根 README、主 Skill README、安装指南、深度环境说明、Quan 截图步骤与测试场景。先说明带什么、另装什么，再给装完第一句话。结果卡位于 `assets/luban-certificate.svg`。

没有制作虚构 GIF。鲁班结构尺剩余五项 WARN 为 Python 脚本不符合其 shell 可执行位启发式、缺 Claude 插件市场元数据、缺真实 GIF／视频、一行 npx 安装未验证、缺 skills.sh 徽章。这些状态保留在报告中。

## 九 执行安排

本轮已完成文件打包、安装指引、检查脚本、规则冲突整理与无扣费验证。下一步由独立用户按新包安装，先确认自己的 MCP 有五项必需工具，再用个人短素材验收深度输出，最后决定一次付费视频测试。

本报告最初随本地依赖套件交付。用户在后续任务已明确授权同步到 danye-mvp，GitHub 更新以本次提交记录为准；标签与其他注册表发布不在本次动作中。
